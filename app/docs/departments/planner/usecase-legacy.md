## 1. 문서 목적

이 문서는 DrinkDiary Android 모바일 애플리케이션의 핵심 사용 흐름을 정의한다.
현재 요구사항 기준으로 앱은 사용자가 마신 주류 기록을 나만의 술 컬렉션으로 관리하고, 재구매를 원하는 술과 내 취향에 맞지 않는 술을 구분할 수 있게 하는 것을 목표로 한다.

## 2. 범위

### 포함 범위

- 주류 종류는 와인, 위스키, 맥주 3종류로 한정한다.
- 사용자는 주류 기록을 등록, 수정, 삭제할 수 있다.
- 주류 기록은 사진, 이름, 가격, 장소, 테이스팅 노트, 별점을 포함한다.
- 사용자는 주류 기록을 재구매 후보, 비선호, 일반 기록으로 구분할 수 있다.
- 사용자는 대시보드에서 주간, 월간, 연간 기준의 컬렉션 현황을 확인할 수 있다.

### 제외 범위

- 사용자 계정, 로그인, 동기화 기능은 현재 범위에 포함하지 않는다.
- 외부 주류 데이터베이스 연동은 현재 범위에 포함하지 않는다.
- 소셜 공유, 추천, 구매 링크, 재고 관리 기능은 현재 범위에 포함하지 않는다.

## 6. 상세 Use Case

### UC-01. 주류 기록 등록

| 항목 | 내용 |
| --- | --- |
| 목적 | 사용자가 마신 주류 경험을 앱에 저장한다. |
| 액터 | 사용자 |
| 사전 조건 | 앱이 실행되어 있고 기록 등록 화면에 접근 가능해야 한다. |
| 사후 조건 | 신규 주류 기록이 로컬 저장소에 저장된다. |

#### 기본 흐름

1. 사용자가 기록 등록 화면을 연다.
2. 앱은 주류 종류 선택 항목을 표시한다.
3. 사용자는 와인, 위스키, 맥주 중 하나를 선택한다.
4. 사용자는 이름, 별점, 컬렉션 상태, 기록 일시를 입력한다.
5. 사용자는 필요 시 사진, 가격, 장소, 테이스팅 노트를 입력한다.
6. 사용자가 저장을 선택한다.
7. 앱은 입력값을 검증한다.
8. 앱은 주류 기록을 저장하고 기록 목록 또는 상세 화면으로 이동한다.

#### 예외 흐름

- 필수값이 누락된 경우 앱은 저장하지 않고 사용자에게 입력이 필요한 항목을 안내한다.
- 사진 접근 권한 또는 이미지 선택이 실패한 경우 앱은 사진 없이 기록을 계속 작성할 수 있게 한다.
- 저장 중 오류가 발생한 경우 앱은 사용자 친화적인 오류 메시지를 표시한다.

### UC-02. 주류 컬렉션 조회

| 항목 | 내용 |
| --- | --- |
| 목적 | 사용자가 저장한 술 컬렉션 기록을 확인한다. |
| 액터 | 사용자 |
| 사전 조건 | 저장된 기록이 있거나 빈 상태를 표시할 수 있어야 한다. |
| 사후 조건 | 사용자는 목록 또는 상세 화면에서 기록 내용을 확인한다. |

#### 기본 흐름

1. 사용자가 컬렉션 목록 화면을 연다.
2. 앱은 저장된 기록을 최신순으로 표시한다.
3. 사용자는 특정 기록을 선택한다.
4. 앱은 선택한 기록의 상세 정보를 표시한다.

#### 예외 흐름

- 저장된 기록이 없으면 앱은 빈 상태 화면과 기록 등록 진입 동선을 표시한다.
- 데이터 조회 중 오류가 발생하면 앱은 오류 상태와 재시도 동선을 제공한다.

### UC-03. 주류 기록 수정

| 항목 | 내용 |
| --- | --- |
| 목적 | 사용자가 기존 주류 기록의 잘못된 정보나 추가 정보를 변경한다. |
| 액터 | 사용자 |
| 사전 조건 | 수정 대상 기록이 존재해야 한다. |
| 사후 조건 | 수정된 정보가 저장되고 이후 조회 화면에 반영된다. |

#### 기본 흐름

1. 사용자가 기록 상세 화면에서 수정을 선택한다.
2. 앱은 기존 값을 입력 폼에 채워 표시한다.
3. 사용자는 필요한 항목을 변경한다.
4. 사용자가 저장을 선택한다.
5. 앱은 입력값을 검증한다.
6. 앱은 수정된 기록을 저장하고 상세 화면에 반영한다.

#### 예외 흐름

- 필수값이 누락된 경우 앱은 저장하지 않고 입력 오류를 표시한다.
- 수정 대상 기록이 삭제되었거나 찾을 수 없으면 앱은 오류 메시지를 표시하고 목록 화면으로 이동한다.

### UC-04. 주류 기록 삭제

| 항목 | 내용 |
| --- | --- |
| 목적 | 사용자가 더 이상 보관하지 않을 주류 기록을 삭제한다. |
| 액터 | 사용자 |
| 사전 조건 | 삭제 대상 기록이 존재해야 한다. |
| 사후 조건 | 해당 기록이 목록과 대시보드 집계에서 제외된다. |

#### 기본 흐름

1. 사용자가 기록 상세 화면에서 삭제를 선택한다.
2. 앱은 삭제 확인 메시지를 표시한다.
3. 사용자가 삭제를 확정한다.
4. 앱은 해당 기록을 삭제한다.
5. 앱은 목록 또는 대시보드 화면으로 이동한다.

#### 예외 흐름

- 사용자가 삭제를 취소하면 앱은 기존 상세 화면을 유지한다.
- 삭제 중 오류가 발생하면 앱은 오류 메시지를 표시하고 기록을 유지한다.

### UC-05. 기간별 대시보드 조회

| 항목 | 내용 |
| --- | --- |
| 목적 | 사용자가 주간, 월간, 연간 기준으로 자신의 술 컬렉션 현황을 빠르게 파악한다. |
| 액터 | 사용자 |
| 사전 조건 | 앱이 저장된 기록을 집계할 수 있어야 한다. |
| 사후 조건 | 사용자는 선택한 기간 기준의 요약 정보를 확인한다. |

#### 기본 흐름

1. 사용자가 대시보드 화면을 연다.
2. 앱은 기본 기간 단위를 표시한다.
3. 사용자는 주간, 월간, 연간 중 하나를 선택한다.
4. 앱은 선택한 기간의 기록을 집계한다.
5. 앱은 기간 내 기록 수, 주류 종류별 비중, 평균 별점, 재구매 후보 수, 비선호 기록 수를 표시한다.
6. 앱은 기간 내 재구매 후보와 비선호 기록 목록을 함께 표시한다.

#### 예외 흐름

- 선택한 기간에 기록이 없으면 앱은 빈 상태와 기록 등록 동선을 표시한다.
- 집계 중 오류가 발생하면 앱은 오류 상태와 재시도 동선을 제공한다.

### UC-06. 주류 종류별 기록 확인

| 항목 | 내용 |
| --- | --- |
| 목적 | 사용자가 와인, 위스키, 맥주별로 자신의 기록을 구분해 확인한다. |
| 액터 | 사용자 |
| 사전 조건 | 기록 목록 또는 대시보드에서 주류 종류 기준 필터를 제공해야 한다. |
| 사후 조건 | 선택한 주류 종류에 해당하는 기록만 표시된다. |

#### 기본 흐름

1. 사용자가 기록 목록 또는 대시보드에서 주류 종류 필터를 선택한다.
2. 앱은 와인, 위스키, 맥주 옵션을 표시한다.
3. 사용자가 특정 주류 종류를 선택한다.
4. 앱은 선택한 주류 종류의 기록만 표시한다.

#### 예외 흐름

- 선택한 주류 종류에 기록이 없으면 앱은 빈 상태를 표시한다.
- 필터 해제를 선택하면 앱은 전체 기록을 다시 표시한다.

## 8. 상태 정의

| 상태 | 설명 |
| --- | --- |
| Loading | 데이터 조회 또는 저장 처리 중 |
| Empty | 표시할 기록이 없음 |
| Success | 기록 또는 대시보드 데이터를 정상 표시 |
| Error | 조회, 저장, 수정, 삭제, 집계 중 오류 발생 |

## 9. 구현 시 고려사항

- 로컬 우선 앱으로 시작하는 것이 적합하다. 이유: 현재 요구사항에 계정, 서버, 동기화가 없기 때문이다.
- 구조화된 기록 저장에는 Room 사용을 권장한다. 이유: 주류 기록은 주류 종류, 기간, 컬렉션 상태 기준의 검색, 필터링, 집계가 필요한 정형 데이터이기 때문이다.
- 설정성 데이터가 추가될 경우 DataStore를 사용한다. 이유: SharedPreferences보다 현대 Android 권장 방식에 가깝기 때문이다.
- UI는 Jetpack Compose와 Material 3 기반으로 구성한다.
- 화면 상태는 ViewModel에서 관리하고 UI는 상태를 렌더링한다. 이유: Composable에 비즈니스 로직이 섞이는 것을 줄이기 위함이다.
- 사진은 URI 기반으로 저장하고 대용량 비트맵을 직접 메모리에 오래 보관하지 않는다. 이유: 모바일 메모리 사용량을 줄이기 위함이다.

## 10. 확인이 필요한 사항

아래 항목은 구현 전에 추가 결정이 필요하다.

1. 가격은 구매 가격인지, 매장 소비 가격인지, 둘 다 허용할지
2. 장소는 자유 입력인지, 지도/위치 권한 기반으로 입력할지
3. 별점 범위는 5점 만점인지, 10점 만점인지
4. 사진은 한 장만 허용할지, 여러 장을 허용할지
5. 컬렉션 상태는 일반 기록, 재구매 후보, 비선호 3개로 충분한지
6. 별점과 컬렉션 상태를 독립적으로 입력할지, 낮은 별점일 때 비선호 제안을 표시할지
7. 대시보드의 기본 기간은 주간, 월간, 연간 중 무엇으로 할지
8. 대시보드에 표시할 지표를 기록 수, 평균 별점, 재구매 후보 수, 비선호 기록 수, 종류별 비중 외에 추가할지
