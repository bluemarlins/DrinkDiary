## 2. 실제로 남은 결함 — 셋 (전부 수정 완료)

### ① 같은 만족도가 화면마다 다른 형식이었다

| 화면 | 이전 | 표시 |
| --- | --- | --- |
| 컬렉션 목록 | `"%.0f".format(rating)` | `3` |
| 기록 상세 | `"%.0f / 5".format(rating)` | `3 / 5` |
| 취향 요약 | `"%.1f점".format(avg)` | `4.7점` |

**한 지표가 세 얼굴을 하면 사용자는 그것을 서로 다른 지표로 읽는다.** 이걸 막으려고 만든
장치가 이미 있었다 — `DrinkLabels`의 주석이 *"같은 것을 다른 말로 부르지 않도록"*이라고
적고 있는데 만족도만 빠져 있었다.

→ `DrinkLabels.rating(Double)` 신설. 정수는 `3점`, 평균은 `4.7점`.
**값이 말하는 만큼만 적는다** — 기록의 만족도는 정수라 소수점이 붙으면 없는 정밀도를 꾸며낸다.

### ② 간격 토큰의 **이름이 명세와 어긋나 있었다**

이게 초판이 놓친 진짜 문제다. 초판은 "20dp가 스케일에 없다"까지만 봤다.

| | `md` | `lg` | `xl` | `xxl` |
| --- | --- | --- | --- | --- |
| 명세 §3.3 | 16 | **20** | 24 | 32 |
| 이전 코드 | 16 | **24** | 32 | 없음 |

**문서를 보고 `lg`를 쓴 사람이 다른 값을 얻는다.** 사용처가 0곳이었던 것은 결과이지 원인이 아니다.

→ 코드를 명세 §3.3 스케일에 이름까지 맞췄고, 화면 가장자리 여백 6곳을 `DrinkDiarySpacing.lg`로
바꿨다. (초판 작업 중 `screen = 20.dp`라는 토큰을 새로 만들려 했으나, **명세에 이미 있는 것을
다른 이름으로 또 만드는 일**이라 철회했다.)

### ③ 목록에서 '안 맞아요'가 보이지 않았다

`37dd5b9`이 재구매만 `★` 한 글자로 표시하고 **비선호는 아무것도 그리지 않았다.**
빈칸이 "그냥 그래요"와 "안 맞아요"를 같은 것으로 만든다 — **구매 판단에서 가장 중요한 신호가
사라진다.** 제품의 목적이 "다음에 뭘 마실까"인데 목록을 훑어서는 그걸 알 수 없었다.

→ 같은 축은 같은 방식으로 적는다. 둘 다 `DDSemanticBadge`로, 문구는 `DrinkLabels`에서.
'그냥 그래요'는 여전히 안 그린다 — 모든 행에 붙으면 소음이고, 표시가 없는 것 자체가
"특별할 것 없었다"로 읽힌다. 비선호를 오류 색으로 칠하지도 않는다. **잘못된 상태가 아니라
취향이 아니었다는 뜻**이고, 부정 신호는 눈에 띄기만 하면 되지 소리칠 필요가 없다.

**에뮬레이터 확인**(기록 6건 보존 상태): 목록에 `안 맞아요` / `또 살래요`가 나타나고
나머지 행에는 아무것도 붙지 않음. 만족도는 목록 `5점·2점·4점`, 취향 요약 `3.8점`.

## 3. 새로 발견한 것 — 미해결 둘

### (a) 명세 내부가 서로 어긋난다

- **§2 표**: 간격 토큰을 `4·8·12·16·24·32`로 적어 **20dp가 빠져 있고**, "임의의 비표준 dp 여백
  흩뿌림 금지"라고 쓴다.
- **§3.3**: `20dp(lg)`를 정식 토큰으로 정의한다.

§3.3을 따라 코드를 맞췄으나, **§2를 읽은 사람은 20dp를 위반으로 판단한다.** 디자인 부서가
어느 쪽을 남길지 정해야 한다.

### (b) 같은 상태에 이름이 둘이다

`DDRepurchaseBadge`의 기본 문구는 `"★ 다시 살래요"`인데
`DrinkLabels.collectionStatus(Repurchase)`는 `"또 살래요"`다. **결함 ①과 같은 종류의 문제**가
컴포넌트 쪽에 남아 있다. 지금은 상세 화면만 이 기본값을 쓰므로 목록과 상세가 같은 상태를
다르게 부른다.

## 4. 결함이 **아닌** 것

일부 화면이 `FilterChip`·`OutlinedTextField`·`Card`를 감싸지 않고 직접 쓴다.
**그대로 두는 것이 맞다.** 래퍼가 값을 하는 경우는 동작이나 규칙이 들어갈 때뿐이고
(`DDProbeQuestion`의 3선택지, `DDScreenScaffold`의 레일/바텀바 분기), 그런 것은 이미 있다.

이 저장소가 만든 또 하나의 공용 장치는 **`DrinkLabels`**다. 위 결함 ①과 3-(b)는 모두
"문구가 한곳에서 오지 않는다"는 같은 뿌리다 — 컴포넌트를 더 만들어서 풀 문제가 아니다.
