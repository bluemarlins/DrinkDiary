F2 프로토타입 · 테이스트 아카이브

취향 입력이 정말 몇 번의 탭으로 끝나는가

PRD F2는 “기본 경로에서 탭 5회 이내, 슬라이더 없음, 일상어만”을 요구합니다. 문서로는 판정할 수 없어서 실제로 눌러보는 프로토타입으로 만들었습니다. 오른쪽 위 카운터가 탭 수를 셉니다. 2026-08-13 검증 반영 — 가운데 선택지를 “보통이었어요”에서 “잘 모르겠어요”로 바꿨습니다.

기록하기 탭 0

무엇을 판단해야 하나

  • 탭 수 — 주종 1회 + 질문 4회 = 5회. PRD 상한과 정확히 같습니다. 이름·사진까지 넣으면 초과합니다.
  • 선택지 문구 — “탄닌 4.5” 대신 “떫었어요”. 입문자가 망설임 없이 고를 수 있는지가 전부입니다.
  • 가운데 선택지 — “잘 모르겠어요”로 확정했습니다. 입문자가 가운데를 고르는 실제 이유는 판단이 안 서는 것이지 “중간이라고 판단”한 게 아닙니다. 모른다고 답할 수 있어야 부담이 사라집니다.
  • 유형 결과 — 자랑하고 싶은 화면인지. 아니라면 F4 공유 카드의 동력이 사라집니다.

설계상 반드시 지킨 것

유형은 한 잔으로 나오지 않는다 한 번의 기록은 데이터 한 점일 뿐입니다. 유형은 여러 기록에서 높게 평가한 것의 경향으로 계산됩니다 — 그래서 프로토타입도 “12개 기록 후”를 시뮬레이션합니다.

축 하나라도 선호를 판정할 수 없으면 유형을 내지 않습니다. 기록 3개로 “당신은 ○○형”이라 단정했다가 사용자가 “아닌데?”라고 느끼면 그 순간부터 앱의 모든 판단이 의심받습니다. ‘판단 유보’ 상태를 눌러 확인해 보세요.

이 프로토타입으로 답해야 할 열린 질문

  • 축이 4개여야 하나 — 3개로 줄이면 탭이 하나 줄지만 유형이 8개가 되어 변별력이 떨어집니다.
  • Unsure가 많으면 유형이 늦게 나온다 — 결함이 아니라 정직함입니다. 다만 UI는 “대비가 부족함”과 “모르겠다고 답함”을 구분해 안내해야 합니다.
  • 짧은 이름의 2축 선택 — 지금은 Body×Intensity입니다. 입문자가 가장 확신 있게 답하는 축이 무엇인지 이 프로토타입으로 확인해야 합니다.
  • 확정 — 영문 4글자 코드, 가운데 선택지는 “잘 모르겠어요”, 선택지 문구 현행 유지.
