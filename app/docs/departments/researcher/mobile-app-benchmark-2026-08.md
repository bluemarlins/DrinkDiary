## 1. 검증 결과 요약 — 세 가지 실패 양상이 이번에도 나왔다

`delegate-research`가 기록한 agy의 실패 양상은 **출처 날조 / 누락 / 조사와 결론의 불일치**다.
이번에는 **날조는 없었고, 누락은 재발했으며, 새 양상이 하나 추가됐다.**

### 1-1. 날조 — 이번에는 없었다 [검증됨]

앱 이름과 개발사를 표본 추출해 확인했다. `Whizzky Whisky Scanner`(Google Play 실재),
`Beanconqueror`(오픈소스 커피 기록 앱, 실재)를 포함해 검색한 항목은 모두 실존했다.

**미검증으로 남긴 것**: `Serializd`, `Waterllama`는 검색 결과가 나오지 않았다. 두 앱 모두
보조 사례로만 쓰였으므로 논지에 영향이 없으나 **인용 시 확인이 필요하다.**

수치 인용은 사실상 하나뿐이었다 — "Nielsen Norman Group, 2020 기준 첫 실행 마찰 최소화 권장".
기관은 실재하고 해당 주제를 다루지만 **특정 문헌을 특정하지 않은 느슨한 인용**이라 [미검증]으로 둔다.

### 1-2. 누락 — 국내 서비스 누락이 세 번째로 재발했다 [검증됨]

**2차 호출의 "같은 카테고리 앱 20종"에 국내 주류 기록 앱이 0종이다.** 목록의 주류 앱은 전부
해외다(Vivino, Distiller, Untappd, CellarTracker, Delectable, RateBeer, Whizzky).

Claude가 교차 검색한 결과 **`글렌 — 위스키 테이스팅 노트`**(App Store, 한국)가 확인됐다.
이름·기능("나만의 노트를 기록하고 테이스팅 히스토리를 확인") 모두 **우리와 가장 가까운
국내 경쟁 앱**이다. `데일리샷`도 확인됐으나 이쪽은 커머스라 성격이 다르다.

> 이 양상은 2026-08 시장 리서치(경쟁 앱 3개만 보고 → 실제 6개 이상), 4축 검증(같은 누락)에
> 이어 **세 번째다.** 모델을 3.6에서 3.7로 올린 뒤에도 재발했으므로 **모델 성능 문제가 아니라
> 위임 구조의 문제**라는 `AGENTS.md`의 진단이 다시 확인됐다.
> → **국내 서비스는 항상 Claude가 교차 검색한다**는 규칙을 계속 지킨다.

### 1-3. 새 양상 — 입력 오염으로 인한 오탐 [오탐]

**3차 호출의 1순위 권고가 통째로 틀렸다.** agy는 다음을 "개발/디자인 명세 텍스트가 UI 리소스에
유출됨"으로 판정하고 **최우선 삭제 대상**으로 올렸다.

```
"2-Column 분할 (좌 40% : 우 60%)"   "36dp 미만 배치 금지"
"Selection Mode 일괄 작업 바"        "온보딩이 길면 여기서 이탈한다"
```

**전부 Kotlin 주석이다.** 화면에 나가지 않는다.

| 문자열 | 실제 위치 |
| --- | --- |
| `36dp 미만 배치 금지` | `ui/component/DDChips.kt:19` — 주석 |
| `Selection Mode 일괄 작업 바` | `ui/component/DDBatchActionBar.kt:17` — 주석 |
| `온보딩이 길면 여기서 이탈한다` | `ui/record/TagPreferencePrompt.kt:23` — 주석 |
| `여운는` (조사 버그로 지목, 10순위) | `ui/profile/TasteTypeCopy.kt:83` — **버그를 막는 유틸을 설명하는 주석** |

**원인은 agy가 아니라 Claude다.** 문구를 뽑을 때 `grep`으로 큰따옴표 안의 한글을 전부 긁어
주석까지 함께 넘겼다. agy는 받은 입력 안에서는 옳게 판단했다.

주석을 제거하고 다시 세니 실제 UI 문구는 **216개**였다(주석 포함 247개). 재추출 후
agy의 지적을 하나씩 대조한 결과는 아래와 같다.

| agy 지적 | 실재 여부 |
| --- | --- |
| `기록했습니다.` 종결어미 불일치 | **실재** |
| `또 살래요` / `다시 살 건가요?` 용어 분열 | **실재** |
| `N개 선택` vs `N개 선택됨` 혼용 | **실재** |
| `아직 취향을 판단하기엔 일러요` | **실재** |
| `기록을 고르세요` 모호 | **실재** |
| `유형을 만드는 축` — '축'은 개발 용어 | **실재** |
| `★ 다시 살래요` | **[오탐]** — T6에서 이미 제거됨 |

**교훈: agy에 우리 코드를 넣어줄 때는 넣는 것이 무엇인지 Claude가 먼저 알아야 한다.**
"파일을 참조하라"고만 하면 날조가 나오고(2026-08-16 T12), 잘못 추출해 넣으면 오탐이 나온다.

## 2. 우리 확정 결정과 충돌하는 권고 [충돌]

**사실 여부와 무관하게 채택하면 안 되는 것들이다.** agy는 우리 명세를 모른다.

### ① 삭제 실행취소 스낵바를 [필수]로 올렸다 — 사용자 결정과 정면 충돌

> agy: "삭제 시 팝업으로 재차 묻는 대신, 하단 스낵바에 `[실행 취소]`를 4~5초간 제공. **[필수]**"

**2026-08-17 사용자 확정은 정반대다** — "되돌리기는 삭제 버튼 후 최종 확인 팝업 한 번만".
`prd.md` F1-2가 "실행취소 스낵바나 휴지통은 만들지 않는다"고 명시한다.

**채택하지 않는다.** 다만 agy가 같은 절에서 요구한 나머지 절반은 **우리가 이미 충족한다** —
"'삭제하시겠습니까?'가 아니라 '기록 N개가 완전히 삭제되며 복구할 수 없습니다'로 비가역성을
명시하라"는 것이 그것이고, 우리 팝업 문구가 정확히 그 형태다.

### ② "3개의 기록을 남기면 첫 테이스트 코드가 열립니다" — PRD가 금지한 약속

> agy: 대시보드 콜드 스타트에 `[1 / 3]` 진행률 게이지와 목표 개수를 제시하라.

`prd.md` 7절-2가 못박는다 — **"앱 어디에도 구체적인 개수를 약속하지 않는다."** 축마다 답이
갈리면 필요한 기록 수가 훨씬 커지므로, 6개라고 말하면 대부분의 사용자에게 거짓말이 된다.

**진행 표시라는 방향은 옳고**(`DDProfileProgressCard`가 이미 그 자리다), **숫자를 약속하는
형태만 안 된다.**

### ③ "당도: 달콤함 75% | 은은함 25%" 형태의 근거 표시 — 우리 알고리즘과 다른 통계

> agy: 요약 아래에 축별 선택 분포 막대를 두어 근거를 보여라.

우리 판정은 **선택 빈도가 아니라 축값과 만족도의 상관**이다(`software-architecture.md` 4-1).
"달콤함 75%"는 *많이 마신 것*을 말하고 우리 결론은 *높게 평가한 것*에서 나온다. 그대로 붙이면
**화면이 근거라고 내놓는 숫자가 실제 판정 근거가 아니게 된다.**

**근거를 보여야 한다는 요구 자체는 타당하다.** 다만 우리가 보여줄 것은 상관의 방향과 표본 수다.

### ④ 색·모서리·외곽선 수치 제안 전량 — 확정 디자인 시스템과 충돌

agy가 제안한 `#D4AF37`(샴페인 골드), `#C85A6E`(로즈), `#0E1512`/`#161F1B`(다크 서피스),
곡률 `12/8/6dp`, "카드 외곽선을 없애라"는 **전부 `design-system.md`와 어긋난다.**

| agy 제안 | 확정 명세 |
| --- | --- |
| 곡률 12/8/6dp | Shape 6/12/18dp (§3.3) |
| 삭제색 `#C85A6E` | `Destructive #BA1A1A` (§3.1, `DesignTokenTest`가 강제) |
| 다크 배경 `#0E1512` | `Paper` Dark `#15110E` (§3.1) |
| "카드 외곽선을 없애라" | §2-6 "**1px의 단정한 외곽선**으로 계층 표현" |

**채택하지 않는다.** T1~T9가 코드를 이 표에 맞추는 작업이었고 `DesignTokenTest`가 지키고 있다.
agy는 우리 팔레트를 모른 채 일반론을 냈을 뿐이다.

### ⑤ "권한 거부 시 설정 유도" — 우리에게는 해당 없음

agy가 [필수]로 올렸으나, 우리는 `ActivityResultContracts.PickVisualMedia`(Android Photo Picker)를
쓴다(`RecordDetailStep.kt:60`). **런타임 권한을 요구하지 않는 API**라 거부 상태가 존재하지 않는다.
체크리스트 항목이 우리 구현에 적용되지 않는 사례로 남긴다.

agy가 [필수]로 올린 것 중 **이미 충족한 항목**이다. 개선 계획에서 빼기 위해 적어 둔다.

- **무손실 마이그레이션** — `MIGRATION_2_3` + `MigrationTest` 3건.
  `fallbackToDestructiveMigration()`은 제거됐고 `harness.md` §1이 재도입을 금지한다.
- **삭제 확인의 구체성** — "N개 기록을 지울까요? … 취향 답까지 함께 지워지고, 되돌릴 수 없어요."

- **즉시 진입** — 온보딩 화면이 없다. 앱을 켜면 바로 대시보드다.

### 3-3. 판단이 필요한 것

- **목록 카드 형태**: agy는 "사진이 없을 때 대형 카드는 회색 빈 공간을 만들어 미완성처럼
  보인다 → 수평 밀도형 카드"를 권한다. 사진이 선택 입력인 우리 조건에 **논리가 맞는다.**

## 4. Claude 종합 판단

**agy의 산출물은 "일반적으로 옳은 체크리스트"로서는 쓸 만하고, "우리 앱에 대한 진단"으로서는
절반이 못 쓴다.** 우리 명세를 모르는 상태에서 나온 권고라 ①~⑤가 확정 결정과 충돌했고,
1순위 권고는 입력 오염으로 무효였다.

**그럼에도 건진 것이 분명하다.** 백업 부재·설정 화면의 상용 최소 요건 3종·작성 중 이탈
방지는 **코드로 확인된 실제 결함**이고, 문구 지적 6건도 실재한다. **대체 텍스트 3곳은 철회했다** —
3-1절 참고. agy만 오탐을 낸 것이 아니라 Claude도 냈다.
특히 **종결어미와 용어가 화면마다 갈라져 있다**는 것은 3판 디자인 감사가 값·구조만 보느라
놓친 층위다.

**사용자가 말한 "학생 프로젝트 수준"의 실체는 시각 디자인이 아니라 이 층위에 가깝다.**
색과 타이포는 T1~T9로 명세에 맞췄고 테스트가 지킨다. 남은 것은 **앱을 실제로 쓸 때 드러나는
것들** — 백업이 없어 데이터가 불안하고, 설정에 버전조차 없고, 작성 중 나가면 날아가고,
같은 것을 화면마다 다르게 부른다.

개선 계획은 `../planner/completeness-improvement-plan-2026-08.md`에 있다.
