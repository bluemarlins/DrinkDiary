## 2. 공통적으로 제공하는 핵심 기능

1. **달력/날짜 기반 캘린더 기록** — 음주한 날과 금주한 날을 시각적으로 구분하여 캘린더에 표시 (이모지, 컬러 칩, 히트맵 방식).
2. **주류 기본 정보 입력 및 이미지 첨부** — 술 이름, 주종(소주, 맥주, 와인, 위스키, 전통주 등), 알코올 도수(ABV), 가격, 마신 장소/구매처, 라벨 사진 업로드.
3. **시음 노트 및 별점/평가** — 1~5점 단위의 별점 평가, 단순 메모 또는 항목별(단맛, 산도, 바디감, 향/피니시) 세부 테이스팅 스코어링.
4. **음주 데이터 통계 및 시각화** — 주간/월별 음주 횟수, 총 음주량(순수 알코올 g), 총 소비 금액, 칼로리 계산 그래프 제공.
5. **데이터 저장 및 동기화** — 소셜 계정 연동을 통한 서버 클라우드 동기화 또는 파일 백업/복원 기능.

## 3. 사용자 리뷰에서 반복적으로 나오는 불만 및 요청 사항

1. **강제 회원가입 및 서버 종속성** — "이메일/카카오 회원가입을 강요한다", "오프라인 환경에서 로딩이 너무 길다"
2. **재구매/비선호 주류에 대한 명확한 분류 부재** — "지난번 마셨던 술이 맛있었는지 일일이 검색해서 찾아봐야 한다", "블랙리스트 전용 태그/필터가 필요하다"
3. **입력 절차의 양극화** — 일반 유저는 세부 테이스팅 입력을 귀찮아하고, 애호가는 세부 기록 항목 부족을 아쉬워함
4. **과도하거나 가시성을 방해하는 광고 배치** — "저장 버튼 누를 때마다 전면 광고가 떠서 흐름이 깨진다", "하단 배너가 버튼을 가려서 터치가 안 된다"
5. **기기 변경 시 데이터 손실 및 백업 미지원** — "재설치하니 기록이 다 날아갔다", "CSV/엑셀/JSON 내보내기가 필요하다"

## 4. DrinkDiary 차별화 포인트

```text
[기존 경쟁 앱]                          [DrinkDiary 차별화 전략]
• 서버/클라우드 필수 (회원가입 요구)  ───►  • 100% 로컬 우선 (오프라인 작동, 노 회원가입)
• 1~5점 단순 별점/긴 리뷰 중심      ───►  • '재구매 후보(Wish)' vs '비선호(Pass)' 직관적 분류
• 복잡한 시음 항목 강제             ───►  • 3초 퀵-로그 vs 상세 테이스팅 노트 선택 제공
• 서버 장애 시 접근 불가             ───►  • 로컬 DB (Room/SQLite) + JSON/CSV 파일 백업
```

1. **100% 로컬 우선 & 즉각적인 실행 속도** — 회원가입 없이 즉시 사용, 네트워크 무관 저장, 개인정보 유출 우려 해소
2. **재구매(Wish) / 비선호(Pass) 탭 필터** — 별점의 애매함 대신 "다시 살까?"에 직관적으로 답하는 UI (DrinkDiary는 이미 `CollectionStatus`로 구현되어 있음)
3. **듀얼 레벨 기록 모드** — 일반 모드(3초 퀵-로그) vs 전문가 모드(세부 테이스팅) — **현재 미구현, 백로그 후보**
4. **투명한 파일 기반 로컬 백업/내보내기** — CSV/JSON export — **현재 미구현, 백로그 후보**
5. **입력 흐름을 방해하지 않는 UX 친화적 광고 설계** — 작성 폼 도중 전면 광고 지양

## 5. 결론: 이 카테고리에서 광고 수익화의 현실성 평가

**평가: "중상(Moderate to High)" — 조건부 양호**

- **긍정 요소**: 주류 기록 앱 사용자는 구매력 있는 2040 성인 타겟이라 광고 단가(CPM/CPC)가 비교적 높게 책정될 가능성. 광고 제거 IAP와의 시너지도 높음.
- **한계 요소**: 접속 빈도가 "술 마시는 날" 위주라 SNS/게임 대비 DAU 기반 배너 광고만으로는 규모 있는 수익 창출에 한계.
- **최종 제안**: 하이브리드 모델 — ① 비침습적 배너(캘린더/통계 화면) ② 1회성 광고 제거 프리미엄 IAP ③ 장기적으로 재구매 리스트 기반 제휴 마케팅 확장.
