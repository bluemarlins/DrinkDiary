| `확인불가` | 1건(프로방스 로제) — **agy가 맞다.** 4개 스타일 그룹에 로제 자리가 없다 |
| 아메리칸 위스키 10종 | 전부 `새오크` — 법정 요건과 일치 |
| 셰리 5종 | 전부 실제 셰리 중심(맥캘란 셰리오크·글렌드로낙·글렌파클라스·아부나흐·하이랜드파크) |
| 아일라 ex-bourbon | 라프로익·아드벡10·탈리스커·쿨일라 모두 `버번` |

"확인불가를 허용한다"는 프롬프트 문구가 이번에도 작동했다. 로제는 사전에서 **뺐다** —
모르는 것을 넣으면 그때부터 사전을 믿을 수 없다.

**정직하게 남길 것**: `혼합`이 64종 중 35종(55%)이고 `셰리`는 5종뿐이다. 시장의 실제 분포이지만,
셰리 취향을 판정하려면 사용자가 셰리 중심 위스키를 3잔은 마셔야 한다.

**설계**: 기록에 사전 id를 저장하지 않고 **이름으로 조회 시점에 찾는다.** 사전을 고치면 과거 기록에도
바로 반영되고, 스키마도 늘지 않는다. 별칭이 입력의 부분 문자열이어야 하므로 "아드벡"만 적으면
매칭되지 않는다 — 어느 아드벡인지 모르는 채로 단정하지 않는다.

에뮬레이터 검증: **캐스크를 한 번도 입력하지 않고** 영문 이름만 6종 적었더니
`셰리 캐스크 4.7점(3잔) / 버번 캐스크 2.3점(3잔)`이 나왔다. 95개 테스트 통과.

**발견한 결함**: FAB가 마지막 줄을 가렸다. 아래 여백만으로는 안 되는데 — **내용이 화면보다 짧으면
스크롤이 아예 생기지 않아** 걷어낼 방법이 없다. `BoxWithConstraints`로 최소 높이를 화면+FAB로
잡아 항상 그만큼은 스크롤되게 했다.

**adb 메모**: `input text`는 **한글을 못 친다.** 한글 이름이 필요한 검증은 영문 별칭으로 우회하거나
별도 IME가 필요하다. 공백은 `%s`로 넘겨야 한 인자로 들어간다.

> 이 변경 이전에 저장된 기록은 `Unsure` 문자열을 갖고 있어 더는 매핑되지 않고 답 단위로 버려진다.
> 출시 전이고 테스트 데이터뿐이라 수용한다(`harness.md` §1 스키마 재정의 예외).

### agy 로스터 3.7 전환 (2026-08-16, 사용자 지시)

**로스터가 4개 → 3개가 됐다.** 플래시 계열을 `gemini-3.5-flash-medium`/`gemini-3.6-flash-high` →
**`gemini-3.7-flash-medium`/`gemini-3.7-flash-high`**로 올리고, **`gemini-3.1-pro-high`를 제외**했다.
남은 셋은 3.7 두 단계 + 승급 티어 `claude-sonnet-4-6`.

`pro-high` 제외는 사용자 판단이다 — **이름만 `pro`일 뿐 세대가 낡아 3.7 플래시보다 사고력도
코드 구성 능력도 떨어진다.** Claude는 처음에 "3.7이 pro보다 낫다는 근거가 하나도 없다"며 남겨뒀는데,
그건 **근거가 없다는 뜻이지 pro가 낫다는 뜻이 아니었다.** 로스터에 남길 이유가 "아직 안 치워봐서"면
그건 이유가 아니다. "무거운 구현" 역할은 `gemini-3.7-flash-high`가 이어받는다.

**부수 효과 하나가 오히려 이득이다.** 모델 선택이 계열 고르기에서 **"얼마나 생각해야 하는 일인가"**
한 가지로 줄었고, 첫 승급이 모델 교체가 아니라 사고 예산 증액이 됐다 — `medium` 실패 + `high` 통과면
원인이 "생각 부족"으로 좁혀지고, **둘 다 실패하면 모델이 아니라 프롬프트나 태스크 분류를 의심해야
한다**는 신호가 된다.

전환 전 확인: `agy models`에 `gemini-3.7-flash-{high,medium,low}` 실재, `gemini-3.7-flash-high`
1회 호출 성공(4.1초, conversation `465534bf-25ba-419f-bb42-7d1692d41d1f`). **문서에 적는 모델 ID가
실제로 돌지 않으면 로스터가 아니라 함정이므로** 표를 고치기 전에 호출해 봤다.

고친 파일: `AGENTS.md`(로스터 표), `harness.md` §6-2(표·로스터 밖 목록·승급 경로),
`agy-playbook.md`(모델 목록·로스터 제약·템플릿 5곳), `persona-registry.artifact.md`(부서별 기본
모델), `software-architecture.md` §8, `.claude/skills/delegate-research/SKILL.md`.

**이력은 승계하지 않았다.** P0-4·P2-5·P1-7·P2-3의 게이트 통과는 3.5/3.6이 받은 성적이라
3.7 행의 "실사용 이력"은 비워 뒀다. 과거 기록(이 로그의 P2-2·P0-4 행, 각 부서 문서의 출처 표기)은
**당시 실제로 쓴 모델을 그대로 남긴다** — 재현 정보를 소급 수정하면 재현이 불가능해진다.
`gemini-3.1-pro-high`의 실사용 기록도 `harness.md` §6-2에 남겼다. 제외된 모델의 기록이지만
거기서 얻은 교훈(구현은 위임 가능, 검증은 아니다 / 미설치 라이브러리 도입 / 스크래치 쓰기)은
**모델이 아니라 agy의 성질**이라 3.7에도 그대로 적용된다.

미검증 하나: **`generate_image`가 3.7에서 되는지 모른다.** 3.6에서 확인했을 뿐이다. §6-2에
이미지 태스크 한정 예외를 두되, 되돌릴 때는 근거를 적도록 했다.

**검증 절차는 축소하지 않았다.** agy의 실패 양상은 모델 성능이 아니라 위임 구조에서 나온다 —
2026-08-15 사전 구축이 깨끗했던 것도 모델이 아니라 **범위를 두 필드로 좁힌 덕이다.**

### DB 재구성 — v3 (2026-08-16)

무결성을 **코드 관례에서 스키마로 옮겼다.** `trait_answers`에 `UNIQUE(recordId, trait)`,
`record_tags`에 `UNIQUE(recordId, category)`.

**왜 지금 중요한가**: 선호 판정이 답 행들의 상관계수라 **중복 한 줄이 계수를 왜곡하는데 에러는
안 난다.** v2까지는 DAO의 "지우고 다시 넣기" 관례만이 이를 막았고, 그 관례를 지나치는 저장 경로가
하나 생기면 끝이었다. 편집 화면을 붙이기 직전이라 그 경로가 늘어나는 시점이다.

**`fallbackToDestructiveMigration()` 제거.** 스키마 재정의가 끝나 예외를 닫았다. 폴백이 남아 있으면
마이그레이션을 빠뜨린 날 **앱은 정상 실행되고 기록만 사라진다** — 즉시 터지는 쪽이 낫다.
`harness.md` §1의 "출시 전 예외"와 `problem-definition.md` 7-1의 방침을 소진 처리했다.

**`@Insert(REPLACE)` → `@Upsert`**: REPLACE는 부모 행을 지웠다 넣으므로 CASCADE로 답·태그가
같이 날아간다. 지금은 바로 뒤에서 다시 넣어 결과가 같았지만 우연이다. 부수 효과로 `@Upsert`는
UPDATE 경로에서 **`-1`을 반환**하므로, 그 값을 recordId로 쓰지 않도록 명시해 뒀다.

**마이그레이션은 실제 데이터를 상대한다.** 유니크 인덱스 생성 전에 중복을 먼저 지운다.
"우리 코드는 중복을 안 만든다"는 전제가 될 수 없다 — 중복 한 줄이면 인덱스 생성이 실패하고
앱이 아예 켜지지 않는다.

검증:

| 방법 | 결과 |
| --- | --- |
| `MigrationTest` 3건 | 통과. **중복 제거를 빼면 `SQLiteConstraintException`으로 실패**하는 것까지 확인 — 테스트가 이유 있게 통과한다 |
| 에뮬레이터 실제 v2 DB | 기록 6·답 24·태그 6에 v3 덮어쓰기 → `user_version` 2→3, 데이터 전량 보존, 크래시 없음 |
| 화면 결과 | `셰리 4.7 / 버번 2.3`, 기록 6개 — 업그레이드 전과 동일 |
| 게이트 | 99개 테스트 · ktlint · lint · assembleDebug 통과 |

`room-testing`은 도입하지 않았다(harness.md §10 — 라이브러리 추가 금지). 대신 v2 스키마를 손으로
세우고 **앱이 실제로 타는 경로**(Room이 `user_version`을 보고 `onUpgrade`를 태우는 경로)를 그대로 탄다.

### 편집 · 설정 화면 (2026-08-16)

**편집(F1-1)**: 상세 → "고치기". 이름·만족도·다시 살까·사진·태그·선택 항목 + **취향 답**까지.

- **폼을 복제하지 않았다.** `RecordDetailStep`을 그대로 쓰고 취향 편집만 슬롯으로 끼웠다.
  복제하면 "이름·만족도 필수" 같은 규칙이 한쪽에만 남는다.
- **ViewModel은 나눴다.** 작성은 탭을 세는 마법사, 편집은 폼이다. 합치면 양쪽이 조건문투성이가 된다.
- **`recordedAtMillis`를 덮지 않는다.** 마신 시각이지 고친 시각이 아니다. 오타를 고쳤다고 그 술을
  오늘 마신 것이 되면 목록 순서가 뒤집힌다. 원본을 `copy`로 덮는 이유가 이것이다.
- **편집 화면이 안 보여주는 고유 축 답도 유지한다.** 저장이 답을 통째로 갈아끼우므로 여기서 빠지면
  사용자가 건드린 적 없는 값이 영영 사라진다.
- 저장 로직을 `DrinkRecord.applying` 순수 함수로 뺐다 — ViewModel 안에 두면 이 규칙들을 검증하려고
  코루틴 테스트 라이브러리를 새로 들여야 한다(harness.md §10).

**설정(F7)**: 기록할 때 물어볼 태그. 그것 하나뿐이다.

- **없는 기능을 자리만 잡아두지 않았다.** 백업·내보내기·Pro는 화면이 생길 때 들어온다.
  동작 안 하는 항목이 보이면 사용자는 앱이 고장난 줄 안다.
- 목록은 `promotableTags` 한 곳에서 온다 — 프롬프트와 갈라지면 **거기서 켠 것을 여기서 끌 수 없다.**
- 스위치는 누르는 즉시 저장한다. "저장" 버튼을 두면 안 누르고 나간다.
- **정직하게 적었다**: "지금 켜도 이미 저장한 기록에는 그 답이 없어요." 숨기면 사용자는
  "왜 아직 아무것도 안 나오지"에서 앱이 고장난 줄 안다.
- 이제 약속할 수 있게 됐으므로 첫 기록 직후 프롬프트 문구에 "설정에서 언제든 바꿀 수 있어요"를 넣었다.

에뮬레이터 검증 — **앱 데이터를 지우지 않고** 마이그레이션으로 살아남은 기록 위에서 그대로:

**대신 실패 양상이 옮겨갔다.** UI 문자열과 개수를 지어냈다:

- 왓챠피디아 `"(3 / 15)"` 진행률 문구 → 확인 불가. **agy 제언 1의 근거 전체가 여기 걸려 있었다**

→ **다음 프롬프트에 넣을 규칙**: *"UI 문구를 큰따옴표로 인용하지 마라."* 지금 규칙은 수치만
막았고 agy는 안 막힌 쪽으로 빈칸을 채웠다. **모델 세대가 아니라 규칙의 구멍 문제다.**

부수 소득: Oura의 진짜 조건(90일 + 수면 30회)이 agy 버전보다 **엄격했다** — 사실이 우리에게 더 유리했다.

**Claude 반론**: agy 제언 3개 중 1개만 채택했다.

- **채택 — Vivino식 양극단 1차원 바** [검증됨]. 우리 4축이 이미 양극단이고 `DrinkLabels.poles()`에
  반대말 쌍이 이미 있다. 지금 F3는 "묵직함" 칩 하나로 끝나 **축 위 어디쯤인지를 못 보여준다.**
- **반대 — 별점 히스토그램**: agy가 §2에서 "사용자는 0~5건 구간에 오래 머문다"고 스스로 써놓고
  수백 편 기준의 Letterboxd 화면을 옮기자고 했다. 6건짜리 5칸 막대는 잡음이다. 게다가 그건
  취향이 아니라 **평점 습관**을 보여준다 — F3의 주제가 아니다.
- **반대 — 진행률 게이지**: 우리 판정은 스칼라가 아니다(축당 표본 6 **그리고** |r| ≥ 0.45).
  **게이지가 100%인데 유형이 안 나오면 지금보다 나쁘다.** 문장은 조건을 얼버무릴 수 있지만
  게이지는 못 한다.

**디자인 시스템 감사 — 초판이 틀렸고 정정했다.** 초판은 *"카탈로그 약 50개 중 실존 6개"*라고
단정했는데, **낡은 작업 트리 스냅샷을 본 것이었다.** 같은 날 커밋 `37dd5b9`(design system v2)이
`DDButtons`·`DDCards`·`DDBadges`를 추가하고 `design-system.md`를 전면 개정·승격한 뒤였다.
실제로는 **`DD*` 16개가 실존하고 화면에서 쓰이고 있다.**

→ **교훈**: 다른 세션이 같은 저장소를 건드릴 수 있다. 대화 중간에 얻은 파일 목록은 스냅샷이지
현재 상태가 아니므로, **감사 직전에 다시 읽어야 한다.**

정정 후 남은 실제 결함은 셋이고 전부 고쳤다(아래 절).

**M3 직접 사용은 결함으로 보지 않는다.** 래퍼가 값을 하는 경우는 동작·규칙이 들어갈 때뿐이고
그런 것은 이미 있다. 남은 문제들의 뿌리는 컴포넌트가 아니라 **문구가 한곳에서 오지 않는 것**이다.

### 디자인 시스템 결함 3건 수정 (2026-08-16)

사용자 지시로 **Claude가 직접** 수정했다(agy 위임 시도는 아래 참조).

| 결함 | 고친 방식 |
| --- | --- |
| 만족도가 `3` / `3 / 5` / `4.7점` 세 형식 | `DrinkLabels.rating(Double)` 신설. 정수는 `3점`, 평균은 `4.7점` — **값이 말하는 만큼만 적는다** |
| 간격 토큰 **이름**이 명세와 어긋남 (명세 `lg`=20, 코드 `lg`=24, 20dp 부재) | 코드를 명세 §3.3 스케일에 이름까지 맞춤. 화면 가장자리 6곳을 `DrinkDiarySpacing.lg`로 |
| 목록에서 **'안 맞아요'가 안 보임** (재구매만 `★`) | 둘 다 `DDSemanticBadge`로. '그냥 그래요'는 계속 안 그린다 |

두 번째 것은 초판이 "토큰 사용처 0곳"까지만 봤는데, **진짜 문제는 이름 불일치**였다 —
문서를 보고 `lg`를 쓴 사람이 다른 값을 얻는다. 사용처 0곳은 결과이지 원인이 아니다.

작업 중 `screen = 20.dp` 토큰을 새로 만들려다 **철회**했다. 명세에 이미 있는 것을 다른 이름으로
또 만드는 일이었다.

에뮬레이터 확인(기록 6건 보존): 목록에 `안 맞아요`/`또 살래요` 노출, 나머지 행은 무표시,
만족도 목록 `5점·2점·4점` / 취향 요약 `3.8점`. 105개 테스트 · ktlint · lint · assembleDebug 통과.

**미해결로 남긴 것 둘** (`../specs/designer/design-system-audit-2026-08.md` 3절):

1. **명세 내부 모순** — §2 표는 간격 토큰에서 20dp를 빼고 "비표준 dp 금지"라고 쓰는데 §3.3은
   `20dp(lg)`를 정식 토큰으로 정의한다. 디자인 부서가 어느 쪽을 남길지 정해야 한다.
2. **같은 상태에 이름이 둘** — `DDRepurchaseBadge`는 `"★ 다시 살래요"`, `DrinkLabels`는
   `"또 살래요"`. 목록과 상세가 같은 상태를 다르게 부른다.

### agy 위임 시도 — 이번엔 못 넘겼다

코드 수정 3건을 agy에 넘기려 했으나 두 번 막혔다.

1. `--dangerously-skip-permissions`가 **분류기에 차단**됨. 우회하지 않고, agy가 코드를 출력하면
   Claude가 검수·적용하는 읽기 전용 방식으로 전환했다.
2. 그 호출이 36초에 `timeout waiting for response`로 실패. **다만 이 시점에 노트북이 절전에
   들어갔다** — 앞선 리서치 호출은 117초 동안 정상 완료했다.

→ **이 실패는 §6-2 로스터 표에 3.7의 실패 이력으로 기록하지 않는다.** 원인이 모델이라는 근거가
없고, 근거 없는 실패 기록은 다음 모델 선택 판단을 오염시킨다. 재시도는 사용자가 중단시켰고
수정은 Claude가 직접 했다.

**남은 제약**: 편집이 필요한 agy 위임은 `--dangerously-skip-permissions` 없이는 비대화형으로
불가능하다. 당분간 agy에는 **조사·초안·코드 출력**만 맡기고 적용은 Claude가 한다.
